# Рекомендации по стандартизации

**ФЕДЕРАЛЬНОЕ АГЕНТСТВО ПО ТЕХНИЧЕСКОМУ РЕГУЛИРОВАНИЮ И МЕТРОЛОГИИ**

---

### П 50.1.112—2016

#### Информационная технология
**КРИПТОГРАФИЧЕСКАЯ ЗАЩИТА ИНФОРМАЦИИ**
**Транспортный ключевой контейнер**

Издание официальное  
Согласовано Министерством информации и коммуникаций РФ  
Ведущие органы: ФГУ «Министерство информации и коммуникаций» РФ

---

### ПРЕДИСЛОВИЕ

В本手册中规定了用于运输安全货物包装的标准。
In this manual, standards are prescribed for the packaging of goods for transport safety.

---

### 1. 概述 (Introduction)

#### 1.1 目的
This document provides guidance on the standards related to information technology for security of transport container packages.
The purpose of this document is to provide guidance on the standards related to information technology for the security of transport container packages.

#### 1.2 适用范围 (Scope)
本手册适用于用于运输安全货物包装的信息技术。
This manual applies to information technology used for packaging goods for transport safety.

#### 1.3 引用标准 (References)
本手册引用的所有标准均遵循国际电工委员会第50-1-112号导则（IEC 50.1:112:2016）。
All standards referenced in this manual follow the IEC 50.1:112:2016 standard guide.

## 4 Представление ключей ГОСТ Р 34.10 и ГОСТ 28147—89

Для обеспечения защиты закрытых ключей от утечек по побочным каналам при считывании и проведении операций с ключами, целесообразно использование маскированных ключей. Для хранения маскированных ключей и наборов масок предлагаются следующие принципы.

Алгоритм наложения маски определен базовой операцией криптографического преобразования алгоритма. Для ключей по ГОСТ Р 34.10 это умножение в поле $F_q$, для ключей по ГОСТ 28147—89 — сложение по модулю 2$^{32}$.

Задана последовательность из $k$ масок $M_1, M_2, \dots, M_k$. Через $M_i(\cdot)$ обозначают операцию наложения $i$-й маски, а через $M^{-1}_i(\cdot)$ — операцию снятия $i$-й маски, $1 \leq i \leq k$. Имеется ключ $K$. Маскированный ключ $K_M$ получается в результате $k$-кратного применения операции наложения маски, а именно $K_M = M_k \dots (M_2(M_1(K)) \dots)$. Демаскирование выполняется при помощи $k$-кратного применения операции снятия маски, но в обратном порядке, и именно $K = M^{-1}_1(\dots (M^{-1}_{k-1}(M^{-1}_k(K_M))) \dots)$. Маскированный ключ представляется как последовательность $I = K_{\parallel} \| M_1 \| M_2 \| \dots \| M_k$, где «$\|$» — операция контаненциации.

Предположим, ключ $K$ имеет $n$ двухочных разрядов, тогда для представления в памяти последовательности $I$ понадобится $(k+1)n$ двоичных разрядов или $k+1 n$-разрядных блоков.

Таким образом, пара ключей для алгоритма по ГОСТ Р 34.10 представлена в виде:
```{GostR3410-2012-KeyValueInfo ::= SEQUENCE {
    GostR3410-2012-KeyValueMask,
    GostR3410-2012-PubKey }
```

$GostR3410-2012-KeyValueMask := OCTET STRING \{ K_M \| M_1 \| M_2 \| \dots \| M_k\}$, и

$GostR3410-2012-PubKey := OCTET STRING \{PubKeyX|PubKeyY\}$.

Для алгоритма ГОСТ 28147—89 ключ представляется в виде:
```{Gost28147-89-Key-KeyValueMask ::= OCTET STRING \{ K_M \| M_1 \| M_2 \| \dots \| M_k \}}
```

Возможно использование незамаскированного закрытого ключа (т. е. $k=0$, $K_M = K$).

Для обеспечения унификации между представлениями ключей в PFX и сертификатах формата X.509, как секретный, так и открытый ключи представляются в формате little-endian (старший байт справа).

Операцией наложения маски является умножение ключа на число, обратное маску:
$$ K_M = K \cdot M^{-1} \mod Q $$
где значение $Q$ взято из параметров ключа. Соответственно операцией снятия маски является умножение маскированного ключа на маску:
$$ K = K_M \cdot M \mod Q.$$

## 4.1 Портфель ключевой информации KeyBag

Version ::= INTEGER

Версия структуры на данный момент равна нулю.

PrivateKey ::= OCTET STRING

Содержимым данным типа является значение закрытого ключа, закодированное в соответствии с типом GostR3410-2012-PrivateKey:

4.2 Данные, защищаемые в транспортном ключевом контейнере
В соответствии с 4.1 [2] каждый раздел транспортных ключевых контейнеров (далее — ТKK), содержащий конфиденциальные сведения, должен быть зашифрован в рамках ContentInfo типа AuthenticatedSafe. Портфель сертификата (CertBag — см. 4.2.3 [2]), соответствующему присутствующему в ТKK портфелю закрытого ключа (KeyBag), несет в себе информацию, облегчающую потенциальную злоумышленнику задачу первичного анализа перехваченного зашифрованного сообщения, в частности по данным, содержащимся в ТKK CertBag, можно получить информацию о владельце секретного ключа. В этой связи содержащийся в ТKK CertBag также может быть зашифрован.
Формирование пароля ключа для шифрования различных ContentInfo и портфелей закрытого ключа KeyBag должен выполняться с использованием секретных разных уникливых синхронизованных пар, исключая повторное использование одного и того же секретного ключа для шифрования различных разделов ТKK.

5 Парольная защита
У отправителя и принимающего имеется предварительное согласованной пароль P. Отправитель с помощью алгоритма дифференцирования выбирает парольный ключ по алгоритму PBKDF2 в соответствии с P 50.1.111—2016 и использует его для шифрования передается за закрытый ключ. Принимает от ТKK.
Целостность ТKK обеспечивается с использованием алгоритма HMAC_GOSTR3411_2012_512 в соответствии с P 50.1.113—2016.
Виду простоты реализации этот способ является наиболее приемлемым для большинства приложений.
Для шифрования различных разделов ТKK используется один и тот же пароль P, но различные случайные значения параметра S длиной от 8 до 32 байт. Пароль должен быть представлен в формате UTF-8 без завершающего нуля и подан на вход алгоритма PBKDF2 в качестве параметра P.

Ключом алгоритма HMAC_GOSTR3411_2012_512 должен быть послужить 32 байта 96-байтовой алгоритма предопределения, выработанной с помощью PBKDF2.
