## Введение

Использование национальных криптографических алгоритмов, определенных ГОСТ Р 34.10 и ГОСТ Р 34.11, в средствах защиты информации осуществляется, как правило, в рамках криптографических протоколов, базированных на сопутствующих алгоритмах.

Находящиеся рекомендации содержат описания сопутствующих алгоритмов, предназначенных для определения псевдослучайных функций протоколов, функций преобразования ключей, согласования ключей по протоколу Диффи-Хеллмана и экспорта ключевого материала.

Необходимость разработки настоящих рекомендаций вызвана потребностью в обеспечении совместимости криптографических протоколов различных производителей, используя алгоритмы ГОСТ Р 34.10 и ГОСТ Р 34.11.

**Примечание — Основная часть настоящих рекомендаций дополнена приложением А.**

## 3 Термники, определения и обозначения

### 3.1 Термники и определения

В настоящих рекомендациях применены следующие термники с соответствующими определениями:

**3.1.1 код аутентификации сообщения на основе хэш-функции НMAC:** Механизм обеспечения аутентичности информации на основе симметричного ключа, построенный с использованием хэш-функции.

**3.1.2 ключ K:** Произвольный элемент из $V_n$, если $K \in V_n$, то его длина равна $n$ бит, где $n$ может быть произвольным натуральным числом.

**3.1.3 псевдослучайная функция PRF:** Отображение, позволяющее выработать псевдослучающие последовательности байтов.

**3.1.4 функция диверсификации KDF:** Отображение, позволяющее порождать производные ключи и ключевой материал по корневым ключу и произвольным данным с использованием псевдослучайной функции.

**3.1.5 выработка ключей обмена VKO:** Алгоритм согласования ключей (основан на алгоритме Диффи-Хеллмана и какой-либо хэш-функции).

**3.1.6 битовое представление:** Для элемента $W = (w^0, w^1, ..., w^{r-1})$, $W \in V_8$ битовым представлением называют вектор $(w_{8r-1}, w_{8r-2}, ..., w_e, w_0) \in V_8r$, где $w^0 = (w_7, w_6, ..., w_0)$, $w^1 = (w_{15}, w_{14}, ..., w_8), ..., w^{r-1} = (w_{8r-1}, w_{8r-2}, ..., w_{8r-8})$ являются элементами пространства $V_8$.

**3.1.7 битовое представление:** Если $n$ кратно $r = n/8$, то битовым представлением элемента $W = (w_{n-1}, w_{n-2}, ..., w_0), W \in V_n$ называют битовым вектором $(w^0, w^1, ..., w^{r-1}) \in V_8r$, где $w^0 = (w_7, w_6, ..., w_0)$, $w^1 = (w_{15}, w_{14}, ..., w_8), ..., w^{r-1} = (w_{8r-1}, w_{8r-2}, ..., w_{8r-8})$ являются элементами пространства $V_8$.

### 3.2 Обозначения

В настоящих рекомендациях используются следующие обозначения:

#### $\oplus$ — операция покомпонентного сложения по модулю 2 двух двоичных строк одинаковой длины;

#### $V_n$ — конечномерное векторное пространство над GF(2) размерности $n$ с операторией сложения $\oplus$; при $n = 0$, пространство $V_0$ состоит из единственного пустого элемента длины 0; если $U$ — элемент $V_n$, то в битовом представлении $U = (u_{n-1}, u_{n-2}, ..., u_1, u_0), u_i \in \{0, 1\}$.

#### $V_8^r$ — множество байтовых векторов длины $r, r \geq 0$; при $n = 0$ пространство $V_0$ состоит из единственного пустого элемента длины 0; если $W$ — элемент $V_8^r$, $r > 0$, то в битовом представлении $W = (w^0, w^1, ..., w^{r-1})$, где $w^0, w^1, ..., w^{r-1}$ принадлежат пространству $V_8$;

#### $A|B$ — конкатенация байтовых векторов $A$ и $B$; если $A = (a^0, a^1, ..., a^{r^{1}-1})$, $A \in V_8^{r^1}$; $B = (b^0, b^1, ..., b^{r^{2}-1}), B \in V_8^{r^2}$, то $A|B = (a^0, a^1, ..., a^{r^{1}-1}, b^0, b^1, ..., b^{r^{2}-1})$, $A|B \in V_8^{r^1} + r^2$;

#### $H_{256}$ — хэш-функция $H$ с длиной выхода, равной 256 битам, определенная в ГОСТ Р 34.11—2012 (раздел 8);

#### $H_{512}$ — хэш-функция $H$ с длиной выхода, равной 256 битам, определенная в ГОСТ Р 34.11—2012 (раздел 8).

### 4.1 Алгоритмы HMAC

В настоящем подразделе определены алгоритмы вычисления кода аутентификации сообщения HMAC на основе хэш-функции $H$, определенной в ГОСТ Р 34.11—2012 (раздел 8) с различными длинами выходных значений.


#### 4.1.1 HMAC_GOSTR3411_2012_256

Алгоритм HMAC_GOSTR3411_2012_256 предназначен для вычисления кода аутентификации сообщения HMAC на основе хэш-функции с длинным выходом, равной 256 битам, определенной в ГОСТ Р 34.11—2012 (раздел 8), и имеет следующий идентификатор:


id-tc26-HMAC-gost-3411-12-256, «1.2.643.7.1.1.4.1».

Результатом работы данного алгоритма является значение функции $HMAC_{256}(K,T)$, вычисление которой для данных $T$ произвольной длины на ключе $K$ длины $n$ бит состоит в формировании байтевой строки $K^*$ длины 64 байта и выполнении преобразований над $K^*$ и данными $T$ с использованием хэш-функции $H_{256}$.

Допускаются любые значения длины $n$ из интервала от 256 до 512.


Для формирования ключа $K^*$ при $n < 512$ следует положить строку равной байтевому представлению $K|A$, где $A = (0,0,\dots,0) \in V_{512-n}$; если $n = 512$, положить $K^*$ равным байтевому представлению $K$. Значение $HMAC_{256}(K,T)$ определено выражением:


$$ HMAC_{256}(K,T) = H_{256} (K^* \oplus ipad \mid H_{256} (K^* \oplus ipad \mid T)), $$

где в байтевом представлении


ipad $=(0x36\ | \ 0x36\ | \ \dots\ | \ 0x36) \in V_8^{64}$,


opad $=(0x5C\ | \ 0x5C\ | \ \dots\ | \ 0x5C) \in V_8^{64}$.

Данный алгоритм использует $H_{256}$ в качестве хэш-функции в конструкции HMAC, описанной в [1]. Указанный способ формирования ipad и opad также приведен в [1]. Длина выхода HMAC$_{256}$ равна 32 байтам, длина блока итерационной процедуры функции сжатия для $H_{256}$ равна 64 байтам (в обозначениях [1]: $L = 32$, $B = 64$).

Алгоритм HMAC_GOSTR3411_2012_512 предназначен для вычисления кода аутентификации сообщения HMAC на основе хэш-функции $H$ с длинным выходом, равной 512 битам, определенной в ГОСТ Р 34.11—2012 (раздел 8), и имеет следующий идентификатор:

#### 4.2.1 Псевдослучающие функции протокола TLS

Преобразование $PRF_{TLS\_GOSTR3411\_2012\_256}$ на основе хэш-функции $H$ с длинной выходом, равной 256 битам, определен в ГОСТ Р 34.11—2012 (раздел 8), дает псевдослучающую функцию протокола TLS (версия 1.0 и выше), используя алгоритм $HMAC_{GOSTR3411\_2012\_256}$, описанную в 4.1.1. $$
PRF_{TLS\_256} (secret, label, seed) = P_{256} (secret, label \mid seed);
$$

$$

$$

$$

$$

Функция $P_{256}$ использует функцию $HMAC_{256}$, описанную в 4.1.1, и соответствует способу задания аргументов и выходного значения функции расширения данных $P_{hash}$, приведенному в разделе 5 [2] и использованном позднее в [5].

\subsection*{4.5 Алгоритм дифференциации $KDF_{TREE}_{GOSTR3411}_{2012\_256}$}

Алгоритм $KDF_{TREE}_{GOSTR3411}_{2012\_256}$ на основе хэш-функции $H$ с длинной выходной, равной 256 битам, определен в ГОСТ Р 34.11—2012 (раздел 8), задает функцию дифференциации, использующую алгоритм $HMAC_{GOSTR3411}_{2012\_256}$, описанном в 4.1.1. Результатом работы данного алгоритма является значение функции $KDF_{TREE}_{256}$; аргументами которой являются байтовые строки $K_{in}, \text{label}, \text{seed и } R$.

$$KDF_{TREE}_{256}(K_{in}, \text{label, seed и } R) = K(1) | K(2) | K(3) | K(4) | \ldots$$

$$K(i) = HMAC_{256}(K_{in}, [i]_b | \text{label} | \text{0x00} | \text{seed} | [L]_b), i \ge 1,$$

где $K_{in}$ — ключ дифференциации;
$\text{label, seed}$ — параметры, задаваемые протоколом, их длины должны быть фиксированы протоколом;
$R$ — внешний фиксуемый параметр, с возможными значениями 1, 2, 3, 4;
$i$ — счетчик числа итераций;
$[i]_b$ — байтовое представление $i$, записьется в сетевом порядке байт;
$[L]_b$ — байтовое представление $L$, записывается в сетевом порядке минимум необходимого числа байт.

Алгоритм дифференциации $KDF_{TREE}_{GOSTR3411}_{2012\_256}$ предназначен для порождания ключа материала длины $L$, не превосходящей 256 $\cdot (2^{8R}-1)$ бит, и использует общие принципы задания входных параметров и выхода для функций дифференциации, изложенных в 5.1 [7]. В качестве псевдослучайной функции выбрана функция $HMAC_{256}$, описанная в 4.1.1.

Если $R = 1$ и $L = 256$, то алгоритм $KDF_{TREE}_{GOSTR3411}_{2012\_256}$ совпадает с алгоритмом $KDF_{GOSTR3411}_{2012\_256}$ из предыдущего подразделения.

Каждый ключ, последовательно полученный из ключевого материала, сформированного с помощью ключевого дифференциатора $K_{in}$ — ключевого уровня 0, можно затем рассматривать как ключ дифференциации 1-го уровня и также использовать для генерации ключевого материала. Ключевым материалом, полученным из ключевого дифференциатора 1-го уровня, может быть разбит на ключи дифференциации 2-го уровня. Применение данной процедуры приводит к построению ключевого дерева с корневым ключом $K_{in}$ и формированию ключевого материала с иерархией по уровням, как описано в разделе 6 [7]. Процедура разбиения ключевого материала на каждом уровне определена в протоколах.

\subsection*{4.6 Экспорт и импорт ключей}

При экспорте секретного ключа $K$ с использованием заданного ключа экспорта $K_e$ и случайного набора $\text{seed}$ длины от 8 до 16 бит формируется экспортное представление ключа $K$ по следующей схеме:
\begin{itemize}
    \item 1) Порождается случайный набор $\text{seed}$.
    \item 2) С помощью функции дифференциации, использующей в качестве ключевого экспорта $K_e$, производится формирование ключа $KEK_e(\text{seed})$:
\end{itemize}

$$KEK_e(\text{seed}) = KDF_{256}(K_e, \text{label}, \text{seed}),$$

<!-- Page 14 -->

где в качестве функции дискретизации используется функция \(KDF_{256}\), описанная в 4.4, при фиксированном значении

\(label = (0x26 \mid 0xBD \mid 0xB8 \mid 0x78)\).

3) Вычисляется значение имитации в соответствии с разделом 5 ГОСТ 28147—89 длины 4 байта от данных \(K\) на ключе \(KEK_e(seed)\), синхроносылка при этом полагается равным первым 8 байтам seed. Полученный набор обозначается через \(SEC_{MAC}\).

4) Ключ защируется в соответствии с разделом 2 ГОСТ 28147—89 в режиме простой замены с использованием ключа \(KEK_e(seed)\). Результат защиты обозначается через \(SEC_{ENC}\).

5) Экспортным представлением ключа полагается набор (seed \(\mid SEC_{ENC} \mid SEC_{MAC}\). При импорте ключа по экспортному представлению ключа и ключу экспорта \(K_e\) восстанавливается ключ \(K\) по следующей схеме:

1) Из экспортного представления ключа выделяются наборы seed, \(SEC_{ENC}\) и \(SEC_{MAC}\).

2) С помощью функции дискретизации, используя в качестве ключа дискретизации ключ экспорта \(K_e\), производится формирование ключа, обозначаемого \(KEK_e(seed)\):

\(KEK_e(seed) = KDF_{256}(K_e, label, seed)\),

где в качестве функции дискретизации используется функция \(KDF_{256}\), описанная в 4.4, при фиксированном значении

\(label = (0x26 \mid 0xBD \mid 0xB8 \mid 0x78)\).

3) Набор \(SEC_{ENC}\) расшифровывается в соответствии с разделом 2 по алгоритму ГОСТ 28147—89 в режиме простой замены с использованием ключа \(KEK_e(seed)\). Ключ \(K\) полагается равным результату расшифровки.

4) Вычисляется значение имитации в соответствии с разделом 5 ГОСТ 28147—89 длины 4 байта от данных \(K\) на ключе \(KEK_e(seed)\), синхроносылка при этом полагается равным первым 8 байтам seed. Если результат отличается от \(SEC_{MAC}\), возвращается ошибка.

Данные алгоритмы экспорта и импорта ключей являются модификациями алгоритмов CryptoPro Key Wrap и CryptoPro Key Unwrap, описанных в 6.3 и 6.4 [4].
