На настоящие рекомендации базируется документ [1], который содержит рекомендации по реализации криптографических механизмов при использовании низкоэнтропийных данных (пароль пользователя), и расширяет его в плане применения соответствующих российских криптографических алгоритмов.

## 3 Обозначения

В настоящих рекомендациях используются следующие обозначения:

### $HMAC_{GOSTR3411}(K, T)$
значение кода аутентификации сообщения, вычисленное для сообщения $T$ на ключе $K$ по алгоритму $HMAC_{GOSTR3411\_2012\_512}$, определенному в P 50.1.113—2016, длина значения равна 512 битам;

### $P$
пароль, представляющий собой символную строку в коде Unix-UTF-8;

### $S$
значение синхроносылок, выбираемое по схеме равновероятного выбора без возврата из множества $B_n$, где $n = 8$, ..., 32;

### $c$
число итераций алгоритма выработки ключа из пароля;

### $dkLen$
длина выходной последовательности (в байтах);

### $DK$
произведенный ключ длиной $dkLen$;

### $\oplus$
операция компонентного сложения по модулю 2 двух двоичных строк одинаковой длины;

### $B_n$
множество байтовых строк длины $n$, $n \geq 0$. Строка $b = (b_1, ..., b_m)$ принадлежит множеством $B_n$, если $b_1, ..., b_m \in \{0, ..., 255\}$. При $n=0$ множество $B_n$ состоит из единственной пустой строки длины 0;

### $\alpha \parallel \beta$
конкатенация двух байтовых строк $(\alpha = (\alpha_{n1}, ..., \alpha_1) \in B_{n1}$ и $\beta = (\beta_{n2}, ..., \beta_1) \in B_{n2}$), то есть строка $\gamma = (\alpha_{n1}, ..., \alpha_1, \beta_{n2}, ..., \beta_1) \in B_{n1+n2}$;

### $MSB_r^n: B_n \to B_r$
функция усиления байтовой строки до размера $r$ путем взятия старых $r$ байт, то есть $MSB_r^n(\alpha, ..., \alpha_{n-r+1}, \alpha_{n-r}, ..., \alpha_1) = (\alpha, ..., \alpha_{n-r+1})$;

### $LSB_r^n: B_n \to B_r$
функция усиления байтовой строки до размера $r$ путем взятия младших $r$ байт, то есть $LSB_r^n(\alpha, ..., \alpha_{n-r+1}, \alpha_{n-r}, ..., \alpha_1) = (\alpha_p, ..., \alpha_1)$;

### $Int(i)$
представление целого непротивочественного числа $i < 2^{32}$ в виде байтовой строки длины 4 $(i_4, i_3, i_2, i_1) \in B_4$, такой что $i = i_1 + i_2 \cdot 2^8 + i_3 \cdot 2^{16} + i_4 \cdot 2^{24}$;

### $b[i.j]$
строка $b[i.j] = (b_1, b_{j+1}, ..., b_j) \in B_{j-i}$, где $1 \leq i \leq j$ и $b=(b_1, ..., b_s) \in B_s$;

### $[x]$
целая часть сверста числа $x$, то есть $[x] = \min \{n \in \mathbb{Z} | n \geq x\}$.

## 4 Алгоритм выработки ключа из пароля

Для выработки ключа $DK$ из пароля $P$ кроме самого пароля используются следующие параметры:
- значение синхроносылок $S$;
- число итераций $c$;
- длину выходной последовательности $dkLen$ (в байтах). Длины приведены в приложении А. Для одного и того же значения пароля значение синхроносылок $S$ должно выбиратьться по схеме равновероятного выбора без возврата из множества $B_n$, где $n = 8$, ..., 32. Рекомендуемое значение пароля $n$ = 32.
Цисло итераций с должно выбиратьться в зависимости от условий эксплуатации и длины пароля (рекомендуемые значения приведены в приложении А).

Ключ $DK$ вычисляется с помощью функции дифференциация HMAC$_{GOSTR3411}$:

$$DK = PBKDF2(P, S, c, dkLen)$$

Функцию дифференциацию вычисляют по следующим алгоритму:
- если $dkLen > (2^{32} - 1) \cdot 64$, то алгоритм завершает работу с ошибкой (неверные параметры);

<!-- Page 7 -->

- вычисляют $n = [dkLen/64]$.
- для каждого $i$ от до $n$ вычисляют набор значений:
    $$U_1(i) = HMAC_{GOSTR3411}(P, S \parallel Int(i)),$$
    $$U_2(i) = HMAC_{GOSTR3411}(P, U_1(i)),$$
    $$\dots,$$
    $$U_c(i) = HMAC_{GOSTR3411}(P, U_{c-1}(i)),$$
    $$T(i) = U_1(i) \oplus U_2(i) \oplus \dots \oplus U_c(i);$$
    - ключ DK вычисляют как concatenацию байтовых строк $T(i)$ с последующим усечением полученной последовательности до длины $dkLen$ выходной последовательности:
    $$DK = MSB^{n,64}_{dkLen}(T(1) \parallel T(2) \parallel \dots \parallel T(n)).$$
    Контрольные примеры для различных значений параметров приведены в приложении Б.

5.1 Зашифрование данных
Процесс зашифрования данных $M$ в схеме PBES2 осуществляется следующим образом:
- выбирается случайное значение $S$ размером от 8 до 32 байт. Рекомендуемая размерность — 32 байта;
- выбирается число итераций с зависимостью от условий эксплуатации и длины пароля (рекомендуемые значения приведены в приложении А);
- устанавливается значение $dkLen = 32$;
- ключ шифрования 4 данных DK вычисляется с помощью функции дифференцировки согласно алгоритму из раздела 4 с использованием параметров $S$, с $dkLen$, то есть $DK = PBKDF2(P, S, c, 32)$;
- значение $ukm$ выбирается случайно равновероятно из множества $B_n$, где $n$ принимает значение 12 или 16 байт в зависимости от выбранного алгоритма шифрования. Для обработки каждого отдельного сообщения на одном начальном ключе используется уникальное значение. Для обраток каждого отдельного отдельного сообщения используется уникальное значение:
    - ГОСТ Р 34.12—2015 «Мага» $n = 12$;
    - ГОСТ Р 34.12—2015 «Кузнецик» $n = 16$;
- устанавливается значение синхроносыкла $S' = ukm[1..n-8]$;
- для алгоритмов id-gostr3412-2015-magma-ctracpkm и id-gostr3412-2015-kuznyechik-ctracpkm данные зашифровываются в соответствии с ГОСТ Р 34.12—2015 в режиме CTR-ACPKM согласно P 1323565.1.017—2018, в качестве начального ключа используется значение $DK$, в качестве синхроносыкла — значение $S'$;

**5.2 Расширение данных**

Процесс расширения данных $C$ с использованием параметров $S$, $c$, $ukm$ в схеме PBES2 осуществляется следующим образом:

1) ключ шифрования сообщения $K(1)$;
2) ключ имитозаторы $K(2)$;

входные параметры для алгоритма $KDF_{TREE}-GOSTR3411_2012\_256$ принимаются следующим значением:

**в)** для полученных расшифрованных данных $M$ с помощью ключа имитозатора $K(2)$, выработанного из $DK$, осуществляется вычисление имитовставки в соответствии с ГОСТ Р 34.12—2015 в режиме выработки имитовставки согласно ГОСТ Р 34.13—2015;

**г)** вычисленное значение имитовставки сравнивается с полученным значением $mac$. При несопадении размеров или значениях сообщение считается искаженным.

**6 Контроль целостности**

В данном разделе описана схема PBMAC1 вычисления контрольной суммы передаваемых данных на основе функции $HMAC_{GOSTR3411}$.

**6.1 Процесс вычисления контрольной суммы**

Процесс вычисления контрольной суммы в схеме PBMAC1 выглядит следующим образом:

- выбирается случайное значение $S$ размером от 8 до 32 байт. Рекомендуемая размерность — 32 байт;
- выбирается число Iterаций с в зависимости от условий эксплуатации и длины пароля (рекомендуемые значения приведены в приложении A);
- устанавливается значение $dkLen$ не менее 32 байт. Значение $dkLen$ выбирается в зависимости от выбранного механизма защиты, использующего выработку ключа из пароля;
- рассчитывается последовательность $K$ с помощью функции дифференцировки согласно алгоритму из раздела 4 с использованием параметров $S$, $c$, $dkLen$, то есть $K = \text{PBKDF2}(P, S, c, dkLen)$;
- для получения контрольной суммы ключ $DK$ путем усечения последовательности $K$ до 32 байт следующим образом: $DK = LSB_{32}^{dkLen}(K)$.

- осуществляется процесс вычисления контрольной суммы с использованием в качестве алгоритма вычисления контрольной суммы функции HMAC_GOSTR3411 на ключе DK;
- параметры S, с сохраняют в качестве параметров алгоритмов в соответствии с разделом 7.3.

### 6.2 Процесс проверки контрольной суммы

Процесс проверки контрольной суммы с использованием параметров S, с в данной схеме PBMAC1 выглядит следующим образом:

- устанавливается значение dkLen не менее 32 байт. Значение dkLen выбирается в зависимости от выбранного механизма защиты, использующего выработку ключа из пароля;
- выполняется последовательность K с помощью функции дифференциации согласно алгоритму из раздела 4 с использованием параметров S, c, dkLen, то есть K = PBKDF2(P, S, c, dkLen);
- для получения контрольной суммы выполняется ключ DK путем усечения последовательности K до 32 байт следующим образом: DK = LSB32^{dkLen}(K);
- осуществляется процесс вычисления контрольной суммы в соответствии с выбранным алгоритмом вычисления контрольной суммы на ключе DK;
- исходящая и полученная контрольные суммы сравниваются между собой. При несопадении размеров или значений сообщение считается искаженным.

8 Вопросы безопасности

При выработке ключевой информации с использованием пароля пользователя необходимо выполнить следующие условия:

- для разных пользователей и для разных сессий одного пользователя необходимо гарантировать уникальность выбора значений синхроносыкла $S$, которые должны выбиратьться по схеме равновероятного выбора без возврата из множества $B_n$, где $n = 8,...,32$;
- для разных пользователей и для разных сессий одного пользователя необходимо гарантировать, что значение с являться одинаковым;
- выбор параметров PBKDF2 должен исключать совпадение ключей, предназначенных для выполнения различных криптографических преобразований;
- для обработки каждого отдельного сообщения на одном начальном ключе необходимо гарантировать уникальность значения $ukm$.
