## ПРЕДИСЛОВИЕ

Настоящие рекомендации содержат описание протокола CRISP — Cryptographic Industrial Security Protocol — неинтерактивного протокола защищенной передачи данных, разработанного для применения в промышленных системах. Протокол CRISP может быть использован для обеспечения конфиденциальности и имитозащиты сообщений и для защиты от наведения повторных сообщений.

Протокол CRISP реализует защиту исходных сообщений путем их опционального шифрования, а также снабжения дополнительными данными, в частности, для обеспечения имитозащиты сообщений и для защиты от наведения повторных сообщений с использованием криптографических методов.

Протокол CRISP не предназначен для взаимодействия в какой-либо либерально определенном протоколе передачи данных. Он представляет собой совокупность набора полетов, правил их формирования и обработки. При этом на защищаемую систему возлагается задача доставки сформированных данных посредством используемых протоколов. В частности, адресация и маршрутизация данных возлагается на защищаемую систему.

3.2 Обозначения
В настоящих рекомендациях использованы следующие обозначения:

$V^*$
— множество всех двочных строк конечной длины, включая пустую строку;

$|x|$
— длина (число компонент) строки $x \in V^*$;

$V_s$
— множество всех двочных строк длины $s$, где $s$ — целое неорицательное число; нумерация подстрок и компонент строки осуществляется справа налево, начиная с нуля;

$x\|y$
— конкатенция двочных строк $x$ и из $V^*$, то есть строка из $|x|$+||$y$' в которой лева подстрока из $V_{|x|}$ совпадает со строкой $x$, а правая подстрока из $V_{|y|}$ совпадает со строкой $y$;

$V_8^*$
— множество всех байтдовых строк длины $i$, имеющих место соответствие между элементами множества $V_8^*$ и $V_8^*$, задаваемое равенством $(a_{i-1},...,a_1,a_0)=x_{8/i - 1}||...|x_{1}|x_0$, где $a_{i-1}=x_{8/i-1}||...|x_{1}|x_0$, где $a_{i-1}=x_{8/i-1}||...|x_{1}|x_0$;

$0^r$
— двочная строка, состоящая из $r$ нулей;

LSBs$_s(x)$: $V^* \setminus \bigcup_{i=0}^{s-1} V_i \to V_s$ — отображение, ставшее в соответствие строке $z_{m-1}$||...||$z_1$|$z_0$, $m \ge s$, строку $z_{s-1}$||...||$z_1$|$z_0$, $z_i \in V_1$, $i=0,1,...,m-1$;

MSBs$_s(x)$: $V^* \setminus \bigcup_{i=0}^{s-1} V_i \to V_s$ — отображение, ставшее в соответствие строке $z_{m-1}$||...||$z_1$|$z_0$, $m \ge s$; строку $z_{m-1}$||...||$z_{m-s+1}$|$z_{m-s}$, $z_i \in V_1$, $i=0,1,...,m-1$;

binary ('string', $l$)
— представление символичой строки string $l$, состоящей из $m$ символов, в виде байовой строки длиной $l$, $l \ge m$, при которой начинается осциллирующий (с сохранением порядка следования символов) перевод исходной строки в байовую строку $(a_{m-1},...,a_1,a_0)$ длиной $m$ в соответствии с ASCII-представлением каждого символа, после чего в случае $l=m$ в качестве результата выдается байовая строка $(a_{m-1},...,a_1,a_0)$, а в случае $l>m$ — байовая строка (0x00,...,0x00, $a_{m-1},...,a_1,a_0$) длиной $l$;

byte ($X$, $I$)
— представление целого числа $X$, $0 \le X \le 2^8-I$ в виде байовой строки длины $I$, при которой соответствующая итоговая байовая строка двочная строка $x_{8/I - 1}$||...|$x_1$|$x_0$, $x \in V_1$, $i=0,1,...,8-I-1$ есть бинарное представление числа $X$, т. е. $X=x_0+x_1\cdot2+\dots+x_{8/I - 1}\cdot 2^{8I-1}$;

K_ENC
— ключ шифрования сообщения;

K_MAC
— ключ имитационный сообщение;

K_Size
— базовый ключ;

Size
— размер окна принятых сообщений.

### 4.1 ExternalKeyFlag

Признак необходимости внешней информации для однозначного определения ключа обработки входящего CRISP-сообщения. Длина поля — 1 бит.

ExternalKeyFlag = 0 означает, что ключ обработки входящего CRISP-сообщения однозначно определяется значением KeyId. ExternalKeyFlag = 1 означает, что для однозначного определения ключа обработки входящего CRISP-сообщения требуется дополнительная информация.

### 4.2 Version

Версия CRISP-сообщения. Беззнаковое целое число. Длина поля — 15 бит.
Текущий документ описывает CRISP-сообщение, для которого Version = 0.

### 4.3 CS

Идентификатор криптографического набора. Беззнаковое целое число. Длина поля — 8 бит.
Идентификатор определяет криптографический набор, используемый для создания CRISP-сообщения или восстановления исходных сообщений из CRISP-сообщений. Всего может существовать не более 256 различных криптонаборов, исходя из 8-битной длины поля CS CRISP-сообщения.

# 6 Обработка CRISP-сообщения

## 6.1 Инцидиализация порядкового номера сообщения и окна принятых сообщений

Перед первым использованием конкретного базового ключа с целью защиты сообщений отправитель устанавливает начальное значение (инициализирует) `SeqNum`. Инцидиализация `SeqNum` может потребоваться также для восстановления после сбоя в номерации сообщений.

Настоящие рекомендации не специфицируют конкретный алгоритм инцидиализации `SeqNum`. При этом алгоритм инцидиализации совместно с правилами формирования порядкового номера исходящих сообщений должны обеспечивать наличие значения `SeqNum` в диапазоне от 0 до $2^{48} -1$ (включительно) и строго возврат одного значения `SeqNum` для каждого сообщения, создаваемого одним отправителем с использованием одного базового ключа.

Перед первым использованием конкретного базового ключа с целью восстановления сообщений получатель устанавливает максимальный и минимальный номер окна принятых сообщений равными 0.

## 6.2 Защита исходного сообщения отправителем

Предполагается, что определен базовый ключ, его идентификатор и криптограф для формирования CRISP-сообщения данному получателю.

Для создания CRISP-сообщения выполняют следующие последовательные действия:

а) формируют порядковый номер сообщений `SeqNum` — текущее значение `SeqNum` увеличивают на 1;

б) из базового ключа выбирают ключи шифрования (в случае криптографическим набором предусмотрено шифрование) и имитозитторы;

в) формируют поля заголовка CRISP-сообщения — поля 1—5 таблицы 1;

г) если криптографическим набором предусмотрено шифрование, то защищают исходное сообщение;

д) вычисляют значение имитовставки `ICV` для заголовка CRISP-сообщения и исходящего сообщения (в случае, если криптографическим набором не предусмотрено шифрование) или заголовка CRISP-сообщения и защищенного сообщения (в случае, если криптографическим набором предусмотрено шифрование) — поля 1—6 таблицы 1.

## 6.3 Восстановление исходного сообщения получателем

Для восстановления исходного сообщения из CRISP-сообщения выполняют следующие последовательные действия:

а) если версия протокола CRISP, указанная в заголовке CRISP-сообщения, не поддерживается получателем, то сообщение блокируют;

б) согласно значению `KeyId` и, в случае `ExternalKeyIdFlag = 1`, дополненной информации определяют базовый ключ;

в) проверяют доступность значения `SeqNum` входящего CRISP-сообщения:

- если значение `SeqNum` входящего CRISP-сообщения меньше минимального номера окна принятых сообщений, то CRISP-сообщение блокируют и процедуру восстановления исходного сообщения прекращают;

- если значение `SeqNum` входящего CRISP-сообщения принадлежит окну принятых сообщений и данным порядковому номеру CRISP-сообщения помечен как принятый в окне принятых сообщений, то CRISP-сообщение блокируют и процедуру восстановления исходного сообщения прекращают.

В остальных случаях значение `SeqNum` входящего CRISP-сообщения является доступным и осуществляют переход к следующим пункту;

г) из базового ключа выбирают ключи шифрования (если криптографическим набором предусмотрено шифрование) и имитозитторы;

д) выполняют контроль целостности CRISP-сообщения путем проверки имитовставки. Если имитовставка не верна, то сообщение блокируют и процедуру восстановления исходного сообщения прекращают; если имитовставка верна, то переходят к следующим пункту;

е) обновляют окно принятых сообщений:

- если значение `SeqNum` входящего CRISP-сообщения принадлежит окну принятых сообщений, то порядковому номеру `SeqNum` помечают в окне принятых сообщений как принятый;

- если значение `SeqNum` входящего CRISP-сообщения больше максимального номера окна принятых сообщений, то новым максимальным номером окна принятых сообщений становится значение

### Введение в теорию и методику регулирования метрополий

#### 1. ГЛАВНЫЙ ЗАДАНИЕ

Генеральный директор ФАО по техническому регулированию и метрологии (ФАОТМ) выразил интерес к проблеме «Взаимодействия между метрополитеном и метрополией». На данный момент этот вопрос не является предметом отдельного научного исследования. Тем не менее, необходимо отметить, что проблема взаимодействия между метрополитеном и метрополией имеет важное значение для обеспечения безопасности и комфорта людей в различных районах города.

#### 2. ОСНОВНЫЕ ПЕРЕМЕННЫЕ

В основе решения этой задачи лежат следующие основные переменные:

*   **Метрополия** — это город, где происходит управление транспортом (метрополити́я).
*   **Метрополитен** — это транспортный узел, который обслуживает метрополитю.
*   **Путешествие** — это процесс движения от одного пункта к другому в метрополити́е.

#### 3. ОСНОВНЫЕ ЗАДАНИЯ

В данной работе рассматриваются следующие основные задачи:

1.  **Определение характеристик системы:** Анализ и определение основных параметров, характеризующих систему управления транспортными средствами.
2.  **Моделирование поведения:** Построение математических моделей для анализа поведения транспортных средств при различных условиях.
3.  **Проектирование:** Разработка концепций и проектов по улучшению качества обслуживания пассажиров и безопасности транспорта.

#### 4. МЕТОДИЧЕСКИЕ ПОЛОЖЕНИЯ

Для решения поставленных задач применяются следующие методы:

*   Методы математического моделирования (моделирование поведения транспортных средств).
*   Простые физические модели, основанные на законах физики и теории относительности.
*   Теорематический подход к анализу системы управления транспортными средствами.
*   Методы анализа данных для оценки эффективности проектов по улучшению качества обслуживания пассажиров.
