Введение \\

Настоящие рекомендации содержат описание протокола выработки общего ключа с аутентификацией на основе пароля. Преобразованим данных, выполняемых при реализации протокола, используют операции в группе точек эллиптической кривой, определенной над конечным простым полем. Стоимость протокола основана на сложности вычислительной задачи Диффи-Хеллмана в группе точек эллиптической кривой и свойствах хэш-функций, а также свойствах кодов аутентификации сообщений, использующих хэш-функции.

Необходимость разработки настоящих рекомендаций вызвана потребностью во внедрении процедур взаимодетствия сторон, обеспечивающих безопасную выработку общей ключевой информации и взаимную аутентификацию при наличии общих исходных конфиденциальных данных малого объема.

Примечание — Основная часть настоящих рекомендаций дополнена приложениями А и Б.

### 1 Область применения

Настоящие рекомендации предназначены для применения в информационных системах, использующих механизмы шифрования и защиты аутентичности данных, с реализацией алгоритмов электронной (цифровой) подписи по ГОСТ Р 34.10 и функции хэширования по ГОСТ Р 34.11 в общедоступных и корпоративных сетях для защиты информации, не содержащей сведений, составляющих государственную тайну.

Описанный в данных рекомендациях протокол предназначен для выработки общего ключа с аутентификацией на основе пароля. Описаны в данном документе рекомендации разделительного протокола пароля и последующей аутентификации при взаимодействии по каналу, в котором допускается присутствие активного противника. Протокол может применяться для обеспечения защиты каналов связи при обработке информации, не содержащей сведений, составляющих государственную тайну. Выработанная сторонами ключевой информация может быть использована для установления защищенного соединения между ними.

## 3 Терминии, определения и обозначения

### 3.1 Термины и определения

В настоящих рекомендациях применены следующие термины с соответствующими определениями:

#### 3.1.1 байтовое представление числа: Вектор $\widetilde{w} = (w_1, \ldots, w_k) \in B_l$ является байтовым представлением числа $w$, если $w=256^{l-1} w_1 + \ldots + 256^0 w_k$.

#### 3.1.2 байтовое представление точки эллиптической кривой: Для точки $\{X, Y\}$ на эллиптической кривой $X \| Y$ этим представлением являються конкатенация байтовых и $Y$ представлений координат этой точки $X$ и $Y$ равна минимально возможной длине байтового представления характеристики поля $p$.

#### 3.2 Обозначения

В настоящих рекомендациях использованы следующие обозначения:

- $E$ — эллиптическая кривая, определенная над конечным полем $F_p$, где $p$ простое, $p > 3$;
- $p$ — модуль эллиптической кривой $E$;
- $a, b$ — коэффициенты уравнения эллиптической кривой $E$ в канонической форме;
- $m$ — порядок группы точек эллиптической кривой $E$;
- $q$ — порядок цикличей подгруппы групп точек эллиптической кривой;
- $P$ — порожающий элемент подгруппы порядка $q$ кривой $E$;
- $X, Y$ — координаты точки эллиптической кривой в канонической форме;
- $O$ — нулевая точка эллиптической кривой;

- $H_{256}$ — хеш-функция $H$ с длиной выхода, равной 256 битам, определенная в ГОСТ Р 34.11—2012 (раздел 8);
- $H_{512}$ — хеш-функция $H$ с длиной выхода, равной 512 битам, определенная в ГОСТ Р 34.11—2012 (раздел 8);
- $HMAC (K,T)$ — значение кода аутентификации сообщения, вычисленное для сообщения $T$ на ключе $K$ по алгоритму HMAC, определенному в P 50.1.113—2016. Длина значения равна 256 бит;

- $F (PW, salt, n)$ — значение функции PBKDF2 $(PW, salt, n)$, определенной в P 50.1.115—2016, где параметр $len$ считается равным 256, если порядок подгруппы $q$ удовлетворяет неравенству $2^{254} < q < 2^{256}$, и равным 512, если $2^{508} < q < 2^{512}$. Согласно P 50.1.115—2016, в функции PBKDF2 в качестве PRF всегда используется функция HMAC с длиной выхода;
- $B_n$ — множество байтовых строк длины $n$, $n \geq 0$. Строка $b = (b_1, \ldots, b_k)$ принадлежит множеству $B_n$, если $b_1, \ldots, b_k \in \{0, \ldots, 255\}$. При $n=0$ множество $B_n$ состоит из единственной пустой строки;
- $\widetilde{w}$ — число $w = 256^{l-1} w_1 + \ldots + 256^0 w_k$, соответствующее вектору $\widetilde{w} = (w_1, \ldots, w_k) \in B_l$;
- $\textbf{\nabla}_{\textbf{int}}(\widetilde{w})$ — число $w = 256^{l-1} w_1 + \ldots + 256^0 w_k$, соответствующее вектору $\widetilde{w} = (w_1, \ldots, w_k) \in B_l$;
- $\textbf{\nabla}_{\textbf{int}}(\widetilde{w})$ — число $w = 256^{l-1} w_1 + \ldots + 256^0 w_k$, соответствующее вектору $\widetilde{w} = (w_1, \ldots, w_k) \in B_l$;
- $\textbf{\nabla}_{\textbf{int}}(\widetilde{w})$ — число $w = 256^{l-1} w_1 + \ldots + 256^0 w_k$, соответствующее вектору $\widetilde{w} = (w_1, \ldots, w_k) \in B_l$;

Примечание — В настоящих рекомендациях используют обозначения параметров эллиптических кривых в соответствии с ГОСТ Р 34.10—2012 (раздел 5).

# 4 Описание протокола

В протоколе участвуют стороны А и Б, между которыми осуществляется выработка общего ключа и взаимная аутентификация на основе пароля.

## 4.1 Параметры протокола

В протоколе могут использоваться несколько эллиптических кривых, для каждой из которых должны быть определены:

- идентификатор кривой $ID_{ALG}$, являющийся байтовой строкой производительной длины;
- точка $P$, являющаяся точкой порождающей элементом подгрупа порядка $q$ данной кривой;
- набор различных точек $\{Q_1, Q_2, ..., Q_N\}$ порядка $q$ на данной эллиптической кривой, где количество точек в точке $N$ является параметром протокола. Метод генерации наборов точек $\{Q_1, Q_2, ..., Q_N\}$ описан в разделе 5.

Параметрами протокола, используемыми стороной А, являются:

1) Хранящийся в тайне пароль $PW$, являющийся байтовой строкой, случайно (псевдослучайно) и равновероятно выбран из множества мощности не менее $10^{10}$ из множества $B_k$, где $k \ge 6$ — длина пароля.
2) Список идентификаторов кривых, поддерживаемых стороной А.
3) Наборы точек $\{Q_1, Q_2, ..., Q_N\}$, соответствующие поддерживаемой стороне А кривым.
4) Счетчик $C_1^A$, контролирующий кол-ско неупущенных попыток аутентификации, предпринятых подряду, и значение $CLim_1$, равное максимально допустимому числу таких событий.
5) Счетчик $C_2^A$, отвечающий за количество неудачных попыток аутентификации, предпринятых за время использования данного значения $PW$, и значение $CLim_2$, равное максимально допустимому числу таких событий.
6) Счетчик $C_3^A$, отвечающий за количество попыток аутентификации (успешных и неудачных), предпринятых для данного значения $PW$, и значение $CLim_3$, равное максимально допустимому числу таких событий.
7) Уникальный идентификатор $ID_A$ стороны А (опционально), являющийся байтовой строкой производительной длины.

Параметрами протокола, используемыми стороной Б, являются:
1) Число $ind \in \{1, ..., N\}$, $salt \in \{1, ..., 2^{18} - 1\}$.
2) Точка $Q_{PW}$, удовлетворяющая равенству

$$Q_{PW} = int (F(PW, salt, 2000)) \cdot Q_{ind}.$$

Примечание — Опционально точка $Q_{PW}$ может не храниться, а вычислиться из $PW$ перед началом работы протокола. В этом случае стороне Б необходимо хранить $PW$ и точки $Q_1$, $Q_2$, ..., $Q_N$.
3) Идентификатор используемой в протоколе эллиптической кривой $ID_{ALG}$.
4) Счетчик $C_1^B$, отвечающий за количество неудачных попыток аутентификации, предпринятых подряду, и значение $Clim_1$, равное максимально допустимому числу таких событий.
5) Счетчик $C_2^B$, отвечающий за количество неудачных попыток аутентификации, предпринятых за время использования данного значения $PW$, и значение $CLim_2$, равное максимально допустимому числу таких событий.
6) Счетчик $C_3^B$, отвечающий за количество попыток аутентификации (успешных и неудачных), предпринятых для данного значения $PW$, и значение $CLim_3$, равное максимально допустимому числу таких событий.
7) Уникальный идентификатор $ID_B$ стороны Б (опционально), являющийся байтовой строкой производительной длины.

## 4.2 Начальные значения счетчиков протокола

После установки пароля $PW$ значения счетчиков аутентификации должны соответствовать следующим ограничениям:

$$- C_1^A = C_1^B = CLim_1, \text{ где } CLim_1 \in \{3, ..., 5\}.$$

4.3 Алгоритм протокола

Описываемый в данных рекомендациях протокол состоит из следующих шагов:
1) Если хотя бы один из счетчиков $C_1^A$, $C_2^A$, $C_3^A$ равен 0, А завершает протокол, возвращая ошибку, информированную об исчерпании числа попыток, контролируемых обновившимся счетчиком.
2) А уменьшает каждый из счетчиков $C_1^A$, $C_2^A$, $C_3^A$ на 1, запрашивая открытую информацию аутентификации у Б и посылает идентификатор $ID_B$.
3) Если хотя бы один из счетчиков $C_1^B$, $C_2^B$, $C_3^B$ равен 0, Б завершает протокол, возвращая ошибку, информированную об исчерпании числа попыток, контролируемых обновившимся счетчиком.
4) Б передает А каждый из счетчиков $ind$, $salt$ и $C_1^B$, $C_2^B$, $C_3^B$ на 1L. Также Б передает А идентификатор $ID_{ALG}$ (дана эта пересылка опциональна). Все дальнейшие вычисления Б проводит в группе точек эллиптической кривой, которая задается идентификатором $ID_{ALG}$.
5) А устанавливает в качестве используемой эллиптической кривой ту, которая задается идентификатором $ID_{ALG}$. Все дальнейшие вычисления А проводит в группе точек этой кривой.
6) А вычисляет точку $Q_{PW}^A = int (F(PW, salt, 2000)) \cdot Q_{ind}$.
7) A случайным образом выбирает обозначение $u_1 = \alpha \cdot P - Q_{PW}^A$ и осуществляет присваивание $z_A = 0$.
8) А посылает B значение $u_1 = \alpha \cdot P - Q_{PW}^A$.
9) B, получив $u_1$, проверяет, что $u_1 \in E$. Если это не так, то B завершает взаимодействие, считая аутентификацию невыполненной.
10) B вычисляет значение $Q_B = u_1 + Q_{PW}$, осуществляет присваивание $z_B = 0$ и случайным образом выбирает величину $\beta \in \{1, ..., q-1\}$.
11) Если $m/q \cdot Q_B = 0$, B осуществляет присваивание $Q_B = \beta P$ и $z_B = 1$.
12) B вычисляет $K_B = H_{256} (\frac{m}{q} \cdot \beta (mod q)) \cdot Q_B$, где хэш-функция считается от байтового представления вычисленной точки.
13) Б посылает А значение $u_2 = \beta \cdot P + Q_{PW}$.
14) A, получив $u_2$, проверяет, что $u_2 \in E$. Если это не так, то A завершает взаимодействие, считая аутентификацию невыполненной.
15) A вычисляет $Q_A = u_2 - Q_{PW}^A$.
16) Если $m/q \cdot Q_A = 0$, то A осуществляет присваивание $Q_A = \alpha P$ и $z_A = 1$.
17) А вычисляет $K_A = H_{256} (\frac{m}{q} \cdot \alpha (mod q)) \cdot Q_A$, где хэш-функция считается от байтового представления вычисленной точки.
18) A вычисляет MAC$_A = HMAC(K_A, 0x01 || ID_A || ind || salt || u_1 || u_2 || DATA_A)$, где DATA_A — опционально присутствующая строка, которая аутентифицируется с помощью MAC$_A$ (если она не используется, то DATA$_A$ считается равной строкой длины 0).
19) A посылает B значение $DATA_A || MAC_A$.
20) В осуществляют проверку на равенство значений $MAC_A$ и $HMAC(K_B, 0x01 || ID_A || ind || salt || u_1 || u_2 || DATA_A)$. Если они не равны, то завершают протокол, считая аутентификацию невыполненной.
21) В завершает протокол, считая аутентификацию невыполненной, если $z_B = 1$.
22) B установивает значение счетчика $C_1^B$ равным $CLim_1$ и увеличивает $C_2^B$ на 1.
23) В устанавливает значение счетчика $C_1^B$ равным $CLim_1$ и увеличивает $C_2^B$ на 1.
24) В вычисляет MAC$_B = HMAC (K_B, 0x02 || ID_B || ind || salt || u_1 || u_2 || DATA_A || DATA_B)$, где DATA$_B$ — опционально присутствующая строка, которая аутентифицируется с помощью MAC$_B$ (если она не используется, то DATA$_B$ считается равной строкой длины 0).
25) B посылает A значение $DATA_A || MAC_B$.
26) А осуществляет проверку на равенство значений $MAC_B$ и $HMAC(K_A, 0x02 || ID_B || ind || salt || u_1 || u_2 || DATA_A || DATA_B)$. Если они не равны, то завершает протокол, считая аутентификацию невыполненной.
27) А завершает протокол, считая аутентификацию невыполненной, если $z_A = 1$.

28) А устанавливает значение счетчика $C_1^A$ равным $C_{lim}^1$ и увеличивает $C_2^A$ на 1. 
После успешного завершения протокола стороны A и B взаимно аутентифицированы и каждая сторона имеет общий выработанный ключ $K = K_A = K_B$. 

Примечания
1 Процесс формирования ключей $K_A$, $K_B$ в пунктах 13 и 18 происходит в соответствии с алгоритмом VKO_ GOSTR3410_2012_256, определенным в P 50.1.113—2016.
2 Использование уникальных идентификаторов $ID_A$ и $ID_B$ является обязательным в том случае, когда начинать процесс взаимодействия может любая из сторон. При этом получатель должен проверить, что полученный им при взаимодействии идентификатор не совпадает с его собственным. В случае совпадения он завершает протокол. В случае если опциональный параметр $ID_A$ (также $ID_B$) не используется хэш-функции в данном случае гарантирует, что его равен любой фиксированной байтовой строке, в том числе строка длины 0.
3 Параметры $ind$, $ID_A$, $ID_B$ и $salt$ могут быть согласованы до начала выполнения действий, описанных в данном разделе. Не один из согласованных параметров не может быть исключен из данных, обрабатываемых функцией HMAC на этапах 19, 21, 24 и 26.
4 Параметр $ID_{ALG}$ может быть зафиксирован или согласован заранее.

В этом случае указанные счетчики могут использоваться для защиты от атака типа «отказ в обслуживании». Например, взаимодействие может возобновляться только после определенной задержки.
6 Возобновление взаимодействия по протоколу в случае обновления одного из счетчиков $C_2^A$, $C_3^A$, $C_2^B$, $C_3^B$ возможно только после смены разделяемого стороной пароля.

5 Построение точек

Для данной эллиптической кривой E с порождающим элементом P алгоритм построения каждой точки Q_i, принадлежащей соответствующей этой кривой набору $\{Q_1, \dots, Q_N\}$, основывается на выборе координат точки с известным преобразованием относительно хэш-функции $H_{256}$, если порядок подгруппы q удовлетворяет неравенству с $2^{254} < q < 2^{256}$, и относительно хэш-функции $H_{512}$, если q удовлетворяет неравенству $2^{508} < q < 2^{512}$, и состоит из следующих шагов:

1) Задать произвольную байтовую строку или более.
2) Вычислить $X = INT(H_{len}(SEED)) \mod p$.
3) Проверить, что значение выражения $X^3 + aX + b$ является квадратичным вычетом в поле $F_p$. Если это не так, вернуться к шагу 1.
4) Выбрать значение Y произвольным образом из множества $\{+\sqrt{R}, -\sqrt{R}\}$, где $R = X^3 + aX + b$. Здесь $\sqrt{R}$ — элемент поля $F_p$, для которого выполнено сравнение $(\sqrt{R})^2 = R \mod p$.
5) Проверить, что для точки Q с координатами (X,Y) выполнены $Q \neq 0$ и $q \cdot Q = 0$. Если это не так, вернуться к шагу 1.
6) С помощью описанного алгоритма для каждой эллиптической кривой E строятся набори точки $\{Q_1, \dots, Q_N\}$. Построенные точки в одном наборе должны иметь различные координаты X.

Примечания — Наличие известного преобразования относительно хэш-функции в данном случае гарантирует построение каждой из точек набора $\{Q_1, \dots, Q_N\}$ доказуемо с помощью известного преобразования. Таким образом, кратность любой из его точек относительно порождающего элемента P и относительно другой точки набора является неизвестной, а задача ее вычисления не существует на практике.
